# БондРадар — клон bondradar.pro

Скринер облигаций Московской биржи. React + Vite, без бэкенда, хостинг на GitHub Pages.

**Сайт:** https://yakotpoliglot-creator.github.io/bond-radar/

## Что внутри

| Раздел | Данные |
|---|---|
| Главная | Кривая доходности ОФЗ, индекс RGBI, индекс корпоратов, **живая ключевая ставка (индекс `KEYRATE`) и RUSFAR**, таблица «Где сейчас доходность», рейтинги «Гособлигации: ОФЗ и регионы», «Корпораты · фикс», «Корпораты · флоатеры», карта рынка «доходность × срок» |
| Скринер | 3095 выпусков (TQCB + TQOB): фильтры по доходности, типу купона, сроку, листингу, обороту + пагинация по 50 |
| Карточка выпуска | Цена, доходность, купоны, НКД, дюрация, оферты, амортизация, график купонных выплат, похожие выпуски |
| Эмитенты | 466 эмитентов, сгруппированных по коду из REGNUMBER (покрытие 2874 выпуска) |
| Подборки | 16 подборок: ОФЗ, флоатеры, валютные, замещающие, ВДО, с офертой, ежемесячный купон, с амортизацией, суборды, короткие, длинные, структурные, 1 уровень, фикс, цена < 90 %, без оферты |
| Акции | 262 акции TQBR (обыкновенные и привилегированные) с оборотами и оценкой капитализации |
| Календарь | Купоны, погашения и оферты рынка: будущая и прошлая неделя |
| Размещения | Анонсы сбора заявок из новостной ленты MOEX. Книги заявок и ориентира купона биржа в API не даёт |
| Портфель / Избранное | Хранятся в localStorage браузера |

## Источник данных

Только **MOEX ISS** (`iss.moex.com`), запросы напрямую из браузера — CORS подтверждён. Бэкенда нет.

Используемые эндпоинты:
- `/engines/stock/markets/bonds/boards/TQCB/securities.json` — корпоративные облигации (3033)
- `/engines/stock/markets/bonds/boards/TQOB/securities.json` — ОФЗ (62). Пересечений с TQCB нет, списки объединяются
- `/securities/{isin}.json` — описание выпуска
- `/securities/{isin}/bondization.json` — график купонов, амортизация, оферты
- `/engines/stock/zcyc.json` — кривая доходности ОФЗ
- `/history/engines/stock/markets/index/securities/{secid}.json` — история индексов. Работают RGBI, RUCBCPNS и RUCBTRNS; базовые RUCBTR/RUCBITR историю не отдают
- `/engines/stock/markets/index/securities.json` — **все индексы одним запросом**: отсюда берутся `KEYRATE` (ключевая ставка ЦБ) и `RUSFAR` (ставка репо с ЦК). Робот-обновлятор ставки не нужен
- `/engines/stock/markets/shares/boards/TQBR/securities.json` — акции (SECTYPE 1 — обычка, 2 — преф; J — ETF, отфильтрованы)
- `/securities.json?q=` — эмитент по ISIN
- `/emitters/{id}.json` — **реестр эмитентов**: ОГРН, юр. и почтовый адрес, сайт, капитализация
- `/sitenews.json` — новостная лента; из неё берутся анонсы первичных размещений
- `/emitters.json` — список всех эмитентов (1486 записей) с ИНН; отсюда робот берёт ИНН для ГИР БО

## Бухгалтерская отчётность из ГИР БО ФНС

На карточке эмитента показывается **выручка и валюта баланса по годам** — из
Государственного информационного ресурса бухгалтерской отчётности ФНС
(`bo.nalog.gov.ru`).

**Правовая основа.** ГИР БО ведётся ФНС по Федеральному закону № 402-ФЗ
«О бухгалтерском учёте», ст. 18 и является публичным ресурсом. Регистрация не нужна,
персональные данные не запрашиваются — используется ИНН **эмитента**, а он и так
публичен в данных биржи.

**Почему нужен робот.** ФНС не отдаёт CORS-заголовок ни на одном своём эндпоинте
(проверено на поиске, карточке организации и выгрузке), поэтому браузер обратиться
к `bo.nalog.gov.ru` не может. Робот `scripts/girbo.mjs` запускается по расписанию
GitHub Actions раз в неделю и кладёт результат в `public/girbo.json`, откуда сайт
читает его с того же домена.

**Что робот соблюдает:**

1. Читает только публичные данные, ничего не обходит и не авторизуется.
2. Если организация закрыла доступ, ФНС отвечает `Organization closed for public use` —
   робот помечает её как `closed`, а сайт показывает честное объяснение. Ограничение
   не обходится.
3. Не собирает персональные данные — только отчётность организаций по их ИНН.
4. Держит паузу между запросами и представляется честным User-Agent со ссылкой на проект.
5. **Не перезаписывает файл, если данных стало заметно меньше** — чтобы сбой сети
   не превратился в обрезанный файл.

### Ловушка, на которой робот сначала не находил никого

ФНС возвращает ИНН **обёрнутым в HTML-подсветку поиска**:

```json
{"id": 10719658, "inn": "<strong>9731004688</strong>", "shortName": "ПАО \"ГК \"САМОЛЕТ\""}
```

Первая версия робота сравнивала строку целиком, поэтому находила **0 организаций
из 375** и выглядела рабочей. Теперь теги снимаются перед сравнением.

## Чего НЕ будет

Данных, которых нет в открытых источниках, на сайте нет — и не будет выдумано. Проверено разведкой по API и сайту биржи:

- **Кредитные рейтинги** (АКРА, Эксперт РА, НКР, НРА) — **проверено трижды**: в описании выпуска 40 полей, в реестре эмитента 14, ни одного рейтингового. Эндпоинты вида `/securities/{id}/ratings.json` — ложное срабатывание: ISS отдаёт обычное описание на любой неизвестный подпуть. На сайте биржи блок «Кредитный рейтинг эмитента» есть, но это пустой `<div id="creditRating">`, который заполняется скриптом.
- **EBITDA, чистый долг, ICR** — требуют полной формы отчётности. ФНС отдаёт открыто только выручку и валюту баланса; полную форму часть организаций закрывает от публичного доступа («Organization closed for public use»), и это ограничение мы не обходим.
- **Первичные размещения с книгой заявок и ориентиром купона** — борды аукционов `AUCT`/`PACT`/`PAYT` в ISS существуют (`is_traded=1`), но содержат **0 бумаг**. Доступны только новостные анонсы — их и показывает раздел «Размещения».
- **Push-уведомления** — нужен сервер.
- **RUONIA и ставки по вкладам** — RUONIA нет среди 868 индексов MOEX, а Банк России не отдаёт данные из браузера (нет CORS). Ставка репо `RUSFAR` есть и показана.

## Как отличить регионы от корпоратов

Без единого дополнительного запроса — по формату государственного регистрационного номера:

```
RU35002GSP0  →  Санкт-Петербург      (RU + 5 цифр + 3 буквы + 1 цифра)
RU35067TMS0  →  Томская область
4B02-11-16493-A-001P  →  корпорат
```

Проверено: **65 региональных выпусков**, пересечение с ОФЗ — ноль. Поле `TYPE` в описании
бумаги (`subfederal_bond`) даёт тот же ответ, но требует отдельного запроса на каждую бумагу;
группы бумаг ISS субфедеральных не выделяет (`/securitygroups.json` — 19 групп, только `stock_bonds`).

## Почему в рейтингах доходности не все выпуски

Доходность к погашению несопоставима при разном горизонте денежного потока. На данных биржи:

| Выпуск | Причина | «Доходность» |
|---|---|---|
| `ТрансФ1P01` | погашение через 10 дней, дюрация 0 | 257 % |
| `Самокат02` | купоны кончаются 31.05.2026 при погашении 23.09.2027 → доходность **к оферте** | 229 % |
| `ИнвОбл01` | погашение через 3 дня | 153 % |

Поэтому в таблицы попадают только выпуски с дюрацией **от 180 дней**, ценой **не ниже 50 %**
номинала и доходностью **до 100 %**. Количество отсеянных видно в шапке таблицы, а строки
с доходностью к оферте помечены. Оставшееся — реальные данные: у `СамолетP15` с доходностью
82 % **32,5 млн ₽ оборота и 3600 сделок** при цене 60 % от номинала.

Вместо этого на карточке выпуска показываются флаги риска, которые MOEX реально отдаёт: `HASDEFAULT`, `HASTECHNICALDEFAULT`, уровень листинга, Z-спред, оборот.

## Ловушка с изменением цены за день

У Мосбиржи в одном и том же ответе лежат **три похожих поля**, и легко взять не то:

| Поле | Что это на самом деле |
|---|---|
| `LASTCHANGE` / `LASTCHANGEPRCNT` | изменение последней сделки **к предыдущей сделке** — шаг между двумя тиками |
| `LASTTOPREVPRICE` | изменение последней цены **к закрытию прошлого дня**, % — то, что нужно |
| `CHANGE` | последняя цена **минус открытие** сегодня, в рублях |

Сначала сайт брал `LASTCHANGEPRCNT`, и это выглядело правдоподобно: значения маленькие, знак иногда совпадает. На самом деле он совпадал с настоящим изменением за день **лишь у 7 % бумаг** — это был шум. Проверено на живых данных:

| Бумага | Показывал сайт | Реально за день |
|---|---|---|
| Сбербанк | 0,00 % | **+1,06 %** |
| ГАЗПРОМ | −0,01 % | **+1,70 %** |
| ЛУКОЙЛ | −0,01 % | **+1,59 %** |
| Роснефть | +0,03 % | **−1,73 %** |
| `МоторТ1Р05` | −10,34 % | **+23,15 %** — знак был противоположным |
| `СЛДК 1P1` | −6,25 % | **−37,50 %** |

Исправлено на `LASTTOPREVPRICE`: сверено с независимым расчётом `(LAST − PREVPRICE) / PREVPRICE` — совпало у **всех 446** торговавшихся акций и у всех торговавшихся облигаций, расхождений нет.

Два случая, когда показывается прочерк, а не число:

- **Сделок сегодня не было** — биржа отдаёт `LAST = null`, а поле изменения `0`. Показать «0,00 %» значило бы соврать: это не «цена не изменилась», а «никто не торговал».
- **Выпуск торгуется первый день** — предыдущего закрытия нет, сравнивать не с чем. Таких новых выпусков в один день набралось 8 при обороте под 200 млн ₽ каждый.

**У индексов поле называется иначе** — `LASTCHANGEPRC`, и оно верное: для RGBI значения 111,22 против 111,69 вчера дают −0,42 %, ровно как в поле. Не заменяйте его на `LASTCHANGEPRCNT` по аналогии с бумагами.

## Z-спред: сколько платят сверх государства

Доходность сама по себе плохо сравнима: 16 % по ОФЗ и 16 % по ВДО — это совершенно разные вещи. Поэтому в скринере есть **Z-спред** — премия бумаги к безрисковой кривой ОФЗ, в процентных пунктах. Он не зависит от уровня ключевой ставки: когда ставка падает, падают и ОФЗ, и корпораты, а спред между ними остаётся.

Биржа отдаёт его готовым в поле `ZSPREAD`. Проверено, что это именно то, чем кажется: **у ОФЗ спред около нуля** (от −2,47 до +1,26, медиана 0,71), **у корпоратов положительный** (медиана 2,81). Заполнен примерно у половины выпусков — биржа считает его только там, где есть корректная дюрация и цена.

**Ловушка.** В том же ответе есть поле `SPREAD`, и оно выглядит как то же самое, но это **спред между лучшими заявками** (0,1; 0,41; 0) — к кредитному риску отношения не имеет. Нужен именно `ZSPREAD`.

**Вторая ловушка.** `ZSPREAD` приходит в **процентных пунктах, а не в базисных**: 46,22 означает 46,22 %, а не 0,46 %. В колонке `zspread` лежало деление на 100 — таблица показала бы 0,46 % вместо 46,22 %. Колонка не выводилась ни в один список, поэтому ошибка не проявлялась, но была настоящей.

**Третья ловушка, самая коварная.** Спред надо проверять на достоверность — но **по тому полю, из которого его считала биржа**, а не по нашей доходности. Наша доходность берётся в первую очередь из `YIELDATPREVWAPRICE`, а `ZSPREAD` считается от `YIELD`, и эти поля расходятся:

| Выпуск | `YIELDATPREVWAPRICE` | `YIELD` | `ZSPREAD` |
|---|---|---|---|
| `ДОМ.РФ25об` | 21,12 % | **2 774,51 %** | **2 759,38** |
| `СэтлГрБ2P4` | — | 36 095,51 % | 36 080,47 |

Первая версия исправления проверяла нашу доходность — и мусор остался: на живой странице у `ДОМ.РФ25об` красовался Z-спред 2 759 %. Правильная проверка — `YIELD` в границах −50…300: после неё диапазон стал **−49,2 … 239,3**, значений `|Z| > 300` не осталось ни одного, а максимум принадлежит реально проблемному `CTRLлиз1Р1` с доходностью 253 %.

## Качество данных

MOEX иногда отдаёт битую доходность: у 7 выпусков `YIELDATPREVWAPRICE` превышает 500 % (максимум — 177 628 %), у 51 — отрицательная; всего помечается 26 выпусков. Такие значения показываются как «н/д» (`ytm: null`, сырое значение сохраняется в `ytmRaw`), в подборках скрываются, а в скринере есть переключатель «Скрыть аномальную доходность» (включён по умолчанию).

Ещё две честные оговорки:

- Подборка «Замещающие» собрана по маркеру «ЗО» в названии (41 выпуск) — биржа не помечает такие бумаги отдельным признаком, поэтому список неполный.
- Цены нет у 336 выпусков из 3095 — по ним не было сделок.

Проверить слой данных на живой бирже:

```bash
node scripts/verify.mjs
```

```

  api/moex.js        слой данных MOEX (нормализация, кэш, подборки)

  components/

```
